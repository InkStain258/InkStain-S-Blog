## 二、关键设计决策

- **搜索不引第三方库**：构建期 `scripts/build-search-index.mjs` 生成 `public/search-index.json`（当前 25 篇 / 255KB），客户端按需加载，权重为标题 > 标签 > 摘要 > 正文，多关键词 AND。
- **阅读偏好走 CSS 变量 + localStorage**：`--reading-size / --reading-leading / --reading-font / --reading-width` 由根节点下发，`.prose` 消费，不改文章内容。
- **站点配置即 JSON**：`SiteContent = typeof siteContent`（`src/config/site-content.json`），新增字段直接加 JSON 并在代码里用 `(siteContent as any).x` 兼容旧数据。本轮新增 `homeLayout`（cards / magazine）与 `decorations`（sakura/fireflies/danmaku/glow/click）。
- **评论分两层**：Gitalk（GitHub 登录，保留）+ 匿名评论（GitHub Issues 当队列，`kind=article` + slug 区分，与留言板共用审核流）。
- **诚实降级**：装饰层默认关；`/admin/health` 只报能验证的问题（构建期能扫的），不做猜测。

## 三、踩过的坑（都是实测踩出来的）

1. **`.card` 是 `position: absolute`**：内容页必须写 `card relative w-full`，否则卡片宽度会撑到 6000px+ 盖住整页。
2. **主题类盖不住站点配色**：配色是运行时写进 `:root` 的**内联**变量，CSS 类优先级不够，`.sepia` 必须 `!important`。
3. **浮层背景透**：`bg-card` 带透明度，弹层要叠 `backdrop-blur` 并显式压一层 `color-mix` 实底，否则背后封面会透出来。
4. **导航卡位置由中心驱动**：`navX = center.x - hiCard/2 - navW - 间距`，`center.x = innerWidth/2`，浏览器缩放会改 `innerWidth` → 卡整体漂移，压正文或飞到画面中间。**正解是让导航与内容用同一套公式**，而不是去量导航卡坐标：
   ```
   outer = max(0, vw - 1460) / 2
   导航 x = outer + 24          容器 mx-auto max-w-[1460px]，内容 pl-330
   ```
5. **Gitalk 的 `loginLink` 不能在实例上覆盖**：`handleLogin` 挂在内部 React 组件上，`new Gitalk()` 返回的对象不是它。有效做法是在捕获阶段拦点击（`.gt-btn-login / .gt-avatar-github`），跳转前把草稿写进 `GT_COMMENT`。
6. **Gitalk 令牌 key 是 `GT_ACCESS_TOKEN`**（草稿是 `GT_COMMENT`），必须在下一次 `render()` 之前写进 localStorage。
7. **本机 `git push` 永久挂起**：GCM 的 `credential-helper-selector` 在非交互 shell 弹不可见窗口。走 `push.py`（读 Windows 凭据管理器里的 OAuth token，绕开 helper）。
8. **本机写 `/tmp` 会 exit 23**（MSYS 映射问题），临时文件用 `$TMPDIR` 或 scratch 目录。
9. **用 curl 发中文会乱码**：bash 传参时被转成 GBK，落进 JSON 就是乱码——这是测试工具的假象，浏览器 `fetch` 发的 UTF-8 完全正常（已验证）。
10. **GitHub 只在登录后才校验 `redirect_uri`**：未登录时合法与非法 URI 返回同一个登录页，所以「回调有没有登记成功」不登录验不出来。
