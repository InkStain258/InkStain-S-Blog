## 二、关键设计决策

- **玻璃不是一个 className，是三级材质 + 三套主题参数**：`--glass-1/2/3-bg`、`--glass-edge-a/b`、`--glass-hi`、`--glass-shadow-1/2/3`，亮 / 纸 / 暗各一套。元素只声明自己属于哪一级，光学参数集中在 `theme.css` 与 `html.sepia`。
- **描边不能只写 1px 单色**：亮色主题 `--ink-border` 就是 `#fff`，白边框压在白卡面上等于没有边界。改双层 `background-image`（填充裁 `padding-box`、渐变边裁 `border-box`）+ `inset 0 1px 0` 内高光，才有玻璃刃口。
- **圆角走 CSS 变量而不是改 @utility**：`@utility card` 里的 `rounded-[40px]` 会被 className 里的 `rounded-xl` 覆盖（产物里更靠后），改成 `border-radius: var(--card-radius, 40px)` 后，页面用 `.card-content { --card-radius: 20px }` 一句话决定，不用在几十个文件里跟优先级打架。
- **进度只留一条**：文章页有目录进度，全站顶部 3px 条只留在列表/首页，避免「两条进度条各说各的」。
- **阅读位置存章节 id 而不是像素**：版心宽度、字号都能被读者改，像素没意义；`localStorage: inkstain:reading-anchor`，按 slug 存 `{id, text, ratio, at}`，最多 80 条，写入 1.2s 节流。
- **空状态统一**：原来是「这里还没有文章」「暂无」「加载中...」四种说法，读者分不清是空了还是坏了；`EmptyState` 统一成图标 + 一句人话 + 一个出口链接。

## 三、本轮踩的坑（都实测过）

1. **`inset 0 0 20` 少个单位，整条 `box-shadow` 被丢弃** —— `@utility card` 里这一行让亮色主题的卡片**一直没有阴影**（暗色的覆盖块单位是对的，所以只有暗色有影子）。症状是「元素很丰富但显得扁」，看配置看不出来，得 `getComputedStyle(el).boxShadow` 才知道是 `none`。
2. **自定义 `@utility` 里的圆角/内边距压不住 className**：`@apply rounded-[40px]` 展开后仍会被 `rounded-xl` 覆盖。要统一切圆角，走 CSS 变量；要覆盖内边距必须 `!p-3`。
3. **`backdrop-filter` 会创建包含块**：移动目录抽屉 `z-[71]` 压不住 `z-40` 的「阅读设置 / 回到顶部」浮动按钮（`elementFromPoint` 证明命中的是按钮）。抽屉必须 `createPortal` 到 `body`。
4. **背景标签页里 framer-motion 不跑动画**：`document.hidden === true` 时文章的 `initial={{opacity:0}}` 永远停在下限，截图是空白页。**别把这种空白当成代码回归**——`Page.bringToFront` + `Emulation.setFocusEmulationEnabled` 之后一切正常。
5. **sticky 侧栏 + 摘要卡会把目录顶出视口**：封面 + 摘要 + 目录三者加起来超过视口高度，目录（和本轮新增的「上次读到」）直接落到屏幕外。给侧栏 `max-h-[calc(100vh-3rem)] overflow-y-auto scrollbar-none`。
6. **受控输入不能先用 native setter 改 value**：那样会破坏 React 的 value tracker，之后的 `input` 事件不再触发 `onChange`，看起来像「搜索没反应」。测搜索用 `Input.insertText`，或者干净页面重载。
7. **纸色主题的卡面与纸面亮度接近**：直接用亮色主题的描边（白 0.9）在 sepia 下完全看不出边界，纸色要单独给更实的暖灰描边和投影。
8. 老坑沿用：`git push` 会永久挂起（走 `push.py`）；`pnpm run build` 触发 `ERR_PNPM_IGNORED_BUILDS`（统一 `npx --no-install next build`）；Lightning CSS 把 `rgba()` 压成 `#rrggbbaa`，验证产物要 grep hex。

### 正文标记为什么解析不了（根因）

这些文章是思源笔记导出的，`**加粗**` 与 `<u>下划线</u>`、`*斜体*` 拼在一起后，落到 CommonMark 的**定界符规则**上就配不成对：

1. `**<u>*文字*</u>**`——三星混排，`**` 与 `*` 互为干扰，整段退化成字面量。
2. `字**<u>词</u>**字`——`**` 前面是汉字、后面紧跟 `<`，两边都不满足「左翼定界符」条件（不能前接字母后接标点），开标记失效。
3. `**……。**例如`——收标记前是句号、后面是汉字，既不是右翼也不是左翼，收不拢。
4. `**词<sup>注</sup>**所`——收标记前是 `>`，同样卡在右翼条件上。
5. `**甲**

****乙**`——思源把相邻两段加粗拼成了 4 个连续星号。

### 修法（先验证再落盘）

写了一个 node 脚本（`marked` 直接渲染 → 去掉标签 → 数残留星号），对每篇做「改前残留 → 改后残留」对照，并且加了一条**纯文本不变量**：剥掉 `*`、`<u>`、`<strong>`、空链接语法后，新旧正文必须逐字相同，否则拒绝写入。

| 规则 | 形态 | 改成 |
|---|---|---|
| E1 | `**<u>*X*</u>**` | `***<u>X</u>***`（三星 + 下划线，斜体保留） |
| E2 | `****` 及以上连续星号 | 删掉（相邻加粗合并回一段） |
| E3 | 汉字紧贴 `**<u>X</u>**` | `<strong><u>X</u></strong>` |
| E4 | `**……。**例如` | `**……**。例如`（句号移出加粗） |
| E5 | `**[文字]()**`、`**<u>散文形式</u>…**` | 去掉空链接 / 换 `<strong>` |
| E6 | `**词<sup>注</sup>**所` | `<strong>词<sup>注</sup></strong>` |

结果：25 篇文章全部 `残留 = 0`，`strong` 元素数持平或增加（合并相邻加粗时略减，视觉等价），正文无字面量 `<u>` / `<strong>` / `<sup>` / `<span>`。

### 交互三件

- **灯箱**：只收 `.prose img` 且 `naturalWidth >= 120` 的图；`gallery.length > 1` 才出左右按钮与 `N / M`；←/→ 循环，滚轮缩放，Esc 关闭，按钮 `stopPropagation`。
- **移动目录抽屉**：`drag='y'` + `dragListener={false}`，只有标题栏能起拖；**`dragConstraints={{top:0,bottom:0}}` 会把抽屉钉死**，手势变死代码——必须给正向下界 + `dragSnapToOrigin`，阈值写 `onDragEnd` 的 `info.offset.y`（实测拖 50px 弹回、拖 230px 关闭）。

### B1 自建图片管线（已上线候选）

不用 `next/image`：Vercel 的图片优化按量计费。改成**构建前用 ffmpeg 预生成**，产物进仓库，运行时只是静态文件。

- `scripts/build-images.mjs`：扫 `public/blogs/**` 与 `public/images/pictures/**` 中 ≥24KB 的图，生成 **480 / 960 两档 AVIF + WebP**，同时写 `public/_img/manifest.json` 与 `src/generated/image-manifest.json`
- `src/components/smart-image.tsx`：命中清单出 `<picture>` + `srcset` + `sizes`；未命中退回普通 `<img>`（仍带 `loading=lazy` / `decoding=async`）；封面传的是 `raw.githubusercontent` 外链时按文件名 + slug 反查站内变体
- 替换点：杂志首页 hero 与卡片、文章侧栏封面、目录卡悬停预览、正文图
- `<picture className='contents'>`：用 `display:contents` 让包裹层不参与布局，避免打断原有 flex / aspect-ratio

**实测（本地生产构建，1440 视口）**

## 批次 A 收尾：Gitalk 密钥轮换（2026-10-31）

### 背景

`/api/gitalk/token` 原先是「环境变量优先 + 源码里的历史值兜底」。那个历史值在 5 个提交里明文出现过（`3301e7f` 起），等于永久泄漏；只要 Vercel 没配变量，线上跑的就是泄露值。

线上自检两次的结果对比：

| 时点 | `GET /api/gitalk/token` |
|---|---|
| 轮换前 | `{"secretSource":"legacy","ok":false}` |
| 轮换后（GitHub 生成新 secret + Vercel 加 `GITALK_CLIENT_SECRET` + 重新部署） | `{"secretSource":"env","ok":true}` |

### 代码改动

- `src/app/api/gitalk/token/route.ts`：删掉 `LEGACY_SECRET` 与回退分支，`resolveSecret()` 只返回 `env` / `none`；缺变量时 `POST` 直接 500「服务端未配置 GITALK_CLIENT_SECRET」，不再悄悄用旧密钥
- `src/app/api/site-check/route.ts`：枚举 `'env' | 'legacy'` → `'env' | 'none'`
- `src/app/admin/health/page.tsx`：未配置时显示「未配置（登录会失败）」，状态灯转红
- `scripts/verify-seo-routes.mjs`：新增**密钥字面量守卫** —— 扫 `src/**/*.{ts,tsx,js,mjs}`（跳过 `generated/`），出现 40 位十六进制即 CI 失败

守卫的价值：这类泄漏都是「图省事把值写进代码」造成的，CI 里卡一道比写文档管用。

### 验收

```
curl -s https://inkstain.top/api/gitalk/token
→ {"secretSource":"env","ok":true}

curl -s -X POST https://inkstain.top/api/gitalk/token -H 'Content-Type: application/json' -d '{"code":"probe-not-real"}'
→ {"error":"The code passed is incorrect or expired.","secretSource":"env"}
```

第二条值得注意：GitHub 返回的是「code 不正确」而不是「client 凭据无效」，说明 `client_id` + 新 `client_secret` 已被 GitHub 接受，新密钥确实生效。

## C1 搜索 2.0：meta + 正文分片按需加载（2026-10-31）

原来的搜索一打开就拉整包 `/search-index.json`（255KB 原始 / 108KB 传输），而且无论查什么词都付这份成本。

### 改法

`scripts/build-search-index.mjs` 现在同时产出三份：

| 文件 | 内容 | 体积 |
|---|---|---|
| `public/search-index.json` | 完整索引（含正文），只给 `/admin/health` 做内容体检 | 255KB |
| `public/search-index/meta.json` | 标题 / 标签 / 摘要 / 日期 / 分类，无正文 | **18KB（gzip 约 6KB）** |
| `public/search-index/body-0..4.json` | 正文按文档序号 %5 分 5 片 | 5 × 42–52KB |

`search-dialog.tsx` 的加载顺序：

1. 打开搜索 → 只取 `meta.json`，首屏结果立刻可交互
2. 输入 ≥2 字后，**只有 meta 命中不足 5 条时**才并行补 5 个正文分片，补完再刷新结果
3. 分片用 `bodyPromise` 去重，一次会话只拉一次，之后走 HTTP 缓存

评分逻辑一行没改（标题 120/60/45 > 标签 30 > 摘要 22 > 正文 10，多词 AND），所以结果排序与改动前完全一致，只是正文命中会比首批结果晚几十毫秒出现。

### 实测（本地生产构建）

| 操作 | 网络请求 |
|---|---|
| 打开搜索框 | `meta.json` 一个请求 |
| 输「比较文学」（常见词，meta 命中够） | 仍只有 `meta.json`，**正文 242KB 没下载** |
| 输「陀思妥耶夫斯基」（只在正文出现） | `meta.json` + `body-0..4.json` 五个分片，命中「文学概论：01 绪论」，摘要显示正文原句 |

### 还没做的

真正的省带宽要靠倒排索引（term → doc ids，按 term 取分片）。这一版是「结构拆分 + 按需加载」，正文总字节没变，只是**不再让常见查询为冷门查询买单**。倒排索引留到下一批，因为它要重写分词（中文按 bigram）与评分，风险和收益都更大。

## B2 续：文章页 JS 820KB → 499KB（2026-10-31）

移动端 390 视口、4G 9Mbps、4 倍 CPU 降频实测线上文章页：**820KB JS / 34 个请求 / 总计 978KB**。逐一归因后做了两处改动，均不改变任何页面行为。

### 1. shiki / katex 按内容决定是否加载

`markdown-renderer.ts` 原本每次渲染都 `Promise.all([loadShiki(), loadKatex()])`。但实测内容：

```
含围栏代码块的文章：0 篇
含数学公式的文章：0 篇
含行内代码的文章：1 篇（不需要 shiki）
```

也就是说 25 篇文章每篇都在为一个用不到的高亮器与公式渲染器付费。现在先做本地字符串判定：

```ts
const needsShiki = /(^|\n)\s*```/.test(markdown)
const needsKatex = markdown.includes('$$') || /(^|[^\])\$[^$\n]+\$/.test(markdown) || …
```

命中才 `import()`，未命中直接跳过。判定只在字符串上做，**不改变渲染结果**：katex 未加载时公式保留原始定界符（原有行为），shiki 未加载时代码块输出未高亮的 `<pre>`（原有 fallback）。

判定用例（`gate-test.mjs` 跑过）：纯文字 / 围栏代码块 / 行内代码 / 行内公式 / 块级公式 / `\(...\)` / `$100 到 $200` 全部符合预期；`\$100` 这类转义美元不会被误判。

### 2. Gitalk 评论区改为进入视口才挂载

文章页底部同时有**两套评论区**：Gitalk（需 GitHub 登录）与匿名评论。Gitalk 的 chunk 是 `790b8da72c53f82e.js`，**777KB 原始 / 160KB gzip**，是整页最重的一份。

新增 `src/components/lazy-mount.tsx`：滚到附近才挂载子树，未挂载时给 120px 占位避免滚动条跳动。

**第一版用 `IntersectionObserver` 是错的**：文章页正文由客户端拉取，首次渲染只有骨架屏那么高，底部这块自然「在视口附近」，观察器立刻触发 —— 本地测不出来（localhost 正文来得快），线上（部署后实测）`.gt-container` 在滚动前就已经存在了。

改成双条件判定：`document.documentElement.scrollHeight > innerHeight * 2`（页面确实长起来了）**且** 元素 rect 进入 `innerHeight + 600px`。用 `scroll` + `resize` + `ResizeObserver(documentElement)` 三处触发，rAF 合帧，挂载后立即解绑。慢网（200ms RTT / 6Mbps）本地复测：滚动前 499KB / `.gt-container` 不存在，滚到底 +171KB / 评论框出现 / 匿名评论框不受影响。

### 实测（本地生产构建，移动端 4G + 4 倍降频）

| 时点 | JS |
|---|---|
| 改动前（线上） | 820KB / 34 请求 / 总计 978KB |
| 去掉 shiki+katex | 658KB / 31 请求 |
| Gitalk 延迟挂载后（未滚动） | **499KB / 总计 620KB** |
| 滚到底部后 | +160KB（Gitalk chunk），`.gt-container` 正常渲染，匿名评论框不受影响 |

### 遗留

评论区仍是两套并存（Gitalk + 匿名）。合并成一套是产品决策，本轮只做延迟加载，没动结构。

## C1 改版：倒排索引 + 服务端搜索（2026-10-31）

上一版把索引拆成 meta + 5 个正文分片，效果是「常见查询 7.8KB」，但**冷门查询仍要拉 5 个分片共 242KB**——根本矛盾没解决：要不要下载正文，取决于这个词冷不冷门，而不是取决于用户需要多少信息。

想清楚一件事：这个站的语料只有 25 篇、13.9 万字。数据这么小，索引放在**服务端**，一次请求返回结果，客户端不需要下载任何索引。这条路的成本是每次查询一次 Serverless 调用（免费额度 100GB·h/月，个人站连万分之一都用不到），而收益是「首结果时间」与词冷不冷门彻底解耦。

### 结构

| 文件 | 作用 | 体积 |
|---|---|---|
| `scripts/build-search-index.mjs` | prebuild 阶段生成两种索引 | — |
| `public/search-index.json` | 完整索引，仅 `/admin/health` 内容体检用 | 255KB |
| `src/generated/search-data.json` | 文档表 + 倒排索引，**打包进服务端函数** | 768KB（不进客户端） |
| `src/lib/search-tokenize.ts` | 分词规则（运行时） | — |
| `src/app/api/search/route.ts` | 查询接口 | — |
| `src/components/search-dialog.tsx` | 只负责输入、防抖、键盘与高亮 | — |

倒排结构：`term → [[docIdx, mask], …]`，mask 位表示命中字段（1 标题 / 2 标签 / 4 摘要 / 8 正文），共 23,532 个 term。

分词规则（构建与查询必须一致，两处都有同款实现并在注释里互相指向）：统一小写；中文按 bigram 切（「比较文学」→ 比较/较文/文学，单字段落保留单字）；拉丁字母与数字按连续串、长度 ≥2；标点当分隔符。

### 查询流程

1. 输入 → 客户端 160ms 防抖 → `GET /api/search?q=`
2. 服务端：分词 → 各 term 文档集合求交（多词 AND）→ 按 mask 加权（标题 45 / 标签 30 / 摘要 22 / 正文 10）+ 整串命中加成（=120 / 前缀 60 / 包含 45）+ 命中位置越靠前越优先
3. 正文片段由服务端从原文截取（命中点前 40 字、后 100 字），客户端只做 `<mark>` 高亮
4. 响应带 `s-maxage=60, stale-while-revalidate=600`，热门词直接吃 CDN

### 实测（本地生产构建）

| 查询 | 结果 | 耗时 | 客户端请求 |
|---|---|---|---|
| 比较文学 | 13 条 | 0ms | 1 个（1.4KB） |
| 陀思妥耶夫斯基（只在正文出现） | 1 条，命中「文学概论：01 绪论」 | 0ms | 1 个 |
| 文心雕龙 | 9 条 | 0ms | 1 个 |
| 林译小说 | 1 条 | 0ms | 1 个 |
| 不存在的词 | 0 条 | 0ms | 1 个 |

对比上一版：常见词 7.8KB、冷门词 7.8KB + 242KB；现在是 **1.4KB，冷门词也一样**。界面加了命中高亮与「N 条结果 · Xms」脚注。

### 副作用与清理

- `public/search-index/`（meta + 正文分片）不再生成，目录已删
- `next.config.ts` 里 `/search-index/:path*` 的缓存规则一并删掉（路径不存在了）
- `layout` 里 meta 预热逻辑删除（客户端不再需要索引）
- `/search-index.json` 保留，仍给 `/admin/health` 用

## Gitalk 初始化收尾（2026-10-31）

2. **空态兜底**：`gitalk-comments.tsx` 加 `MutationObserver`，一旦出现 `.gt-no-init` 就把文案换成
   「这篇还没有人用 GitHub 号讨论过。登录后发第一条就行，评论区会自动建好对应的话题。」

### 仍需人工

真实登录一次（浏览器停在 GitHub 登录墙，无法代填账号密码）。登录后 Gitalk 会写入 `GT_ACCESS_TOKEN`，之后发评论走 `/api/github` 代理 + 服务端 secret。

## 部署失败复盘：两处根因（2026-10-31）

P0 推上去连挂两次部署（`2dc2ce2`、`6ea9ac1`），GitHub 只回「Deployment has failed」，Vercel 日志要登录才能看。用**与 Vercel 同一条命令** `pnpm build` 在本地复现，两个原因都很具体：

**根因一：pnpm 11 不再读 package.json 里的 `pnpm` 字段**

本地 `pnpm build` 会在跑脚本前做依赖状态检查（`runDepsStatusCheck`），内部调 `pnpm install`，而 `pnpm install` 因 `ERR_PNPM_IGNORED_BUILDS`（esbuild / sharp / workerd 的安装脚本没被放行）返回 1，整条 build 就挂了。

放行配置写在 `pnpm-workspace.yaml`：

```yaml
allowBuilds:
  esbuild: true
  sharp: true
  workerd: true
```

注意两点：① 旧键 `onlyBuiltDependencies` 在 pnpm 11 不再生效（`pnpm config list` 会提示 `The "pnpm" field in package.json is no longer read`）；② pnpm 会在 `pnpm install` 时**自动往 pnpm-workspace.yaml 里插入 `allowBuilds` 模板**，值是 `set this to true or false` —— 那不是注释，是没填的占位符，必须改成 `true`。

**根因二：`tailwindcss-animate` 不是未使用依赖**

我按「0 引用」把它删了，但 `src/styles/globals.css` 第 7 行是 Tailwind v4 的 CSS 优先写法：

```css
@plugin 'tailwindcss-animate';
```

删除后 `next build` 在 PostCSS 阶段直接失败。已装回 devDependencies 并锁 1.0.7。

**教训**：判断「依赖未使用」不能只 grep TS 文件——CSS-first 的 Tailwind v4 插件（`@plugin`）不在 `import` 里。删依赖前必须同时 grep `*.css`，并以 `pnpm build`（不是 `npx next build`）作为放行标准。

本地 `pnpm build` 通过后推送 `3b11bae`，部署 `7485657030` success。

## 批次 P9：移动端竖屏适配（2026-10-31）

用户在手机上反馈「不能适配竖屏、还要手指左右移动」。用 CDP 390×844 模拟逐项量，找到三个真问题。

### 1. 整页根本不能滚（最严重）

| 指标 | 改前 | 改后 |
|---|---|---|
| `document.documentElement.scrollHeight` | **844**（= 视口高） | 2943 |
| `document.body.scrollHeight` | 2943 | 2943 |
| window 滚动 | 滚动落在 body 上 | 正常 |

原因链：`<main className='h-full'>` 把 main 锁在 100vh，内容溢出但不撑高页面；再叠加 `html, body { overflow-x: hidden }`——CSS 规范规定一个方向 hidden 时另一个方向会算成 `auto`，于是 **body 变成滚动容器**，`window.scrollY` 恒为 0，所有依赖滚动的功能（阅读进度条、回到顶部、TOC 高亮）在手机上全废。

修法：

- `main` 的 `h-full` → `min-h-full`
- 移动端的 `overflow-x: hidden` → **`overflow-x: clip`**（clip 只裁剪，不创建滚动容器，不会把 overflow-y 变成 auto）

### 2. 顶部导航左侧跑出屏幕 + 最后一个图标被主题按钮盖住

改前 `cardLeft = -7`（负值，首图标被裁）、卡片宽 404 在 390 屏上必然溢出；右上角固定的主题切换按钮又把最右的烧瓶盖掉一半。

- 宽度改为 `min(404, 视口宽 - 76)`，给主题按钮留位置
- 移动端定位改成左对齐 `{x: 12, y: 10}`，不再用 `center.x`（它记的是初始化那一刻的窗口中心，旋转屏幕后就过期）
- `useSize` 增加实时 `width` 字段，窗口变化时定位跟着重算
- 窄屏图标间距 `gap-4 → max-sm:gap-1.5`

实测 390 视口：卡片 337px、left 27…改后卡片不再溢出，`navRight 313 / themeLeft 330`，不再重叠。

### 3. 长标题被右边缘硬切

`PostList` 的条目一直是 `truncate`，窄屏上「比较文学笔记：13 文学范围内比较研究的若干领域6—」被切成半句。改成 `max-sm:line-clamp-2`（手机上两行），桌面仍是单行省略。

### 4. 横向兜底

移动端 `html, body { overflow-x: clip }`，正文表格与图片 `max-width: 100%`，表格单独允许内部横向滚动（`display:block; overflow-x:auto`）。

## 批次 P9：移动端适配（2026-10-31）

### 根因：viewport 被手写死，用户根本放不大

`src/layout/head.tsx` 里手写了一份 viewport：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no" />
```

同时 `src/app/layout.tsx` 的 `export const viewport` 又让 Next 输出第二份 `width=device-width, initial-scale=1`。**一个页面两个 viewport meta**，浏览器取第一个 —— 于是：

- `user-scalable=no` + `maximum-scale=1.0`：手机上双指放大被禁用（违反 WCAG 1.4.4）
- 字小的时候只能凑近看或拖动，这正是「不能适配竖屏、还得用手指移动」的来源

修法：

1. 删掉 `layout/head.tsx` 里那行 viewport
2. `layout.tsx` 的 viewport 导出补 `width: 'device-width'`、`initialScale: 1`、`viewportFit: 'cover'`（**不设 maximum-scale**，允许缩放）

实测构建产物：`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover"/>` 只剩一份。

> 排查时又踩了一次老坑：改完构建后 curl 仍返回旧的两份 meta，原因是端口上残留着上一轮的 `next start` 进程在服务旧产物。kill 掉所有 342x 端口的进程后立刻正确。

### 安全区

`viewport-fit=cover` 后内容会铺到刘海和 home indicator 下面，补：

```css
body { padding-left/right: env(safe-area-inset-left/right) }
#main-content { padding-bottom: env(safe-area-inset-bottom) }
```

## 批次 P10：页脚改为点击展开（2026-10-31）

### 问题

`site-footer.tsx` 里有一段：

```js
const mq = window.matchMedia('(hover: hover) and (pointer: fine)')
if (!mq.matches) setOpen(true)      // 触屏设备强制常驻展开
const expanded = open || !canHover   // 于是永远为 true
```

设计意图是「触屏没有 hover，就让它一直展开」，实际效果是**手机上页脚永远展开、永不收起**，而且展开面板是 `absolute inset-x-0 bottom-0`，会向上盖住正文 → 遮挡。

### 改法

| 项 | 旧 | 新 |
|---|---|---|
| 触发方式 | hover 进入自动展开、离开自动收起（触屏强制展开） | **只有点击**，无自动弹出 |
| 默认态 | 触屏常驻展开 | **默认收起**（`open = false`） |
| 展开定位 | `absolute bottom-0` 浮在正文上 | `relative`，在文档流里**撑开页脚**，把内容往下推，不覆盖 |
| 展开入口 | 「悬停展开」提示文字 | `<button>` 「展开页脚」，带 `aria-expanded` / `aria-controls` |

## 修复：审核面板回复框光标乱跳（2026-11-02）

### 根因

`manage/page.tsx` 把 `Item` 定义在组件函数**内部**：

```tsx
export default function GuestbookManagePage() {
  ...
  const Item = ({ m, mode }) => { ... }   // ← 每次渲染都是新函数
}
```

React 靠函数引用判断组件类型。父组件每输入一个字符都会 `setReplyText` 重渲染 → `Item` 变成一个新的组件类型 → React 把整棵子树**卸载再挂载** → `<textarea>` 被重建、`autoFocus` 重新触发、光标位置丢失。表现就是「打一个字光标跳一次」。

### 修法

把 `Item` 提到模块顶层，改成普通函数组件，通过 props 接收 `open` / `replyText` / `onReplyText` / `onAct` / `onToggle` / `busy`。组件类型稳定后，重渲染只更新 props，textarea 不再被重建。

### 验证

`next dev` + 本地文件驱动造一条留言：

| 步骤 | 结果 |
|---|---|
| 输口令进入 | 「待审核 0 / 已展示 1」 |
| 点「回复」 | textarea 出现且 `document.activeElement === textarea` |
| 逐字输入 a → b → c | `value: "abc"`，`cursor: 3`，`activeElement: TEXTAREA`，`textarea 数量: 1` |

修复前同样的操作会是 value 只剩最后一位（或空）且焦点丢失。

### 3. 首页动态背景

新增 `.home-aurora`：三团 54–62px 高斯模糊的光斑（青 / 紫 / 青绿），用 `transform: translate3d + scale` 做 46s / 58s / 52s 三条不同周期的漂移，`will-change: transform` 交给 GPU 合成，不动 `background-position`（避免每帧重绘）。固定在视口，`z-index: 0`，内容层 `relative z-10`。

| 亮色 | 0.20 / 0.17 / 0.18 |
| 暗色 | 0.50 / 0.42 / 0.40 |

`prefers-reduced-motion: reduce` 下动画关闭，光斑静止仍在。移动端 blur 降到 46px。

## 玻璃调色参照归档卡 + 修复 reduced-motion 下内容全隐（2026-11-02）

### 1. 填充从「单色平铺」改成「上亮下暗」

参考 `/blog` 归档卡的观感：卡片是垂直渐变，顶部受光偏亮，往下收到深蓝，背景光晕能透出来。原来 `glass-*` 用 `linear-gradient(bg, bg)` 单色平铺，整体是一块死板的面。

| 主题 | `--glass-1-top` | `--glass-1-bot` |
|---|---|---|
| 暗色 | `rgb(110 132 214 / 0.27)` ≈ `#333f6b` | `rgb(48 62 122 / 0.14)` ≈ `#242c48` |
| 亮色 | `#ffffffd1` | `#ffffff9e` |
| 纸色 | `#fdf9f1f2` | `#f7efe1d9` |

`glass-2` 在同一个色相上各加一档（暗色 0.35 / 0.20），`glass-overlay` 单独给一组近实底。

模糊同时收一点，让后景色块透得出来：`glass-1` 16px → **14px**，`glass-2` 24px → **20px**（saturate 提到 1.18 / 1.20，颜色不至于发灰）。

### 2. 顺手修一个真实 bug

`.ink-fade-up` / `.ink-card-in` 这些类靠 `animation-fill-mode: both` 把 `opacity` 从 0 拉到 1。`prefers-reduced-motion: reduce` 下 `animation: none !important` 一关，元素就永远停在 `opacity: 0` —— 开了「减少动效」的用户看到的是一片空白。

同一现象在「页面在后台标签打开」时也会出现（CSS 动画不推进）。

修：reduced-motion 块里显式补 `opacity: 1 !important; transform: none !important;`。

排查方法记录：截图空白但 `document.body.innerText` 有内容、`document.visibilityState === 'hidden'` → 先 `Page.bringToFront` 再截，否则会误判成样式坏了。

### 验收

| 检查 | 结果 |
|---|---|
| 暗色 `glass-1` | `linear-gradient(rgba(110,132,214,0.27) 0%, rgba(48,62,122,0.14) 100%)` |
| `glass-1` blur | `blur(14px) saturate(1.18)` |
| `/blog` 时间模式 | 卡片与参考图一致：顶部受光、下部收暗、左侧极光透入 |
| 首页 | 实验室按钮、hero 文字卡、导航卡同一套渐变语言 |

## 玻璃回到深海军蓝 + 全站动态背景（2026-11-02）

### 问题

上一版按归档卡取色改成了亮蓝紫（top `rgb(110 132 214 / 0.27)` ≈ `#333f6b`），整体发浅发灰。用户要的是「颜色深、晶莹剔透」——深色玻璃的剔透感不来自填充亮度，来自**强高光 + 亮描边 + 背后有东西可透**。

### 1. 填充回到 `#16213e` 系

| 变量（暗色） | 亮蓝紫版 | 现在 |
|---|---|---|
| `--glass-1-top` | `rgb(110 132 214 / 0.27)` | `rgb(30 46 92 / 0.66)` ≈ 上沿 `#1e2e5c` |
| `--glass-1-bot` | `rgb(48 62 122 / 0.14)` | `rgb(13 21 44 / 0.58)` ≈ 下沿 `#0d152c` |
| `--glass-2-top/bot` | 0.35 / 0.20 | `rgb(34 52 102 / 0.76)` / `rgb(15 24 50 / 0.68)` |
| `--glass-edge-a` | 白 30% | 白 **40%** |
| `--glass-hi`（上沿高光） | 白 26% | 白 **34%** |
| 新增 `--glass-lo`（下沿暗线） | — | 暗色 `rgb(0 0 0 / 0.34)`，亮色 `rgb(20 40 50 / 0.06)`，纸色 `rgb(88 66 40 / 0.07)` |

`box-shadow` 从「上高光 + 外投影」变成「上高光 + 下暗线 + 外投影」，多了 1px 的厚度感。blur 回调到 16 / 22px，saturate 1.22 / 1.24。

### 2. 极光从首页搬到全站

深色玻璃要透，背后得有光。`.home-aurora` 改名 `.site-aurora`，移进 `RootLayout`，`z-index: -1`（在 `html` 背景之上、正文之下），暗色浓度降到 0.38 / 0.32 / 0.30（比首页原值淡），亮色 0.20 / 0.17 / 0.18。

首页不再单独渲染一份。

### 验收

| 页面 | 结果 |
|---|---|
| `/` | 极光 3 团，`z-index: -1`，玻璃卡透出青色光 |
| `/blog`（时间模式） | 卡片深蓝、顶部白高光、下沿暗线，左上角透出背景青光 |
| `/blog/wxgl6` | 正文大卡不动（可读性优先），右侧摘要/目录卡走新玻璃 |

## 玻璃大幅提透（靠 blur 保可读）+ 首页实验室换统计面板（2026-11-02）

### 1. 玻璃 alpha 砍到 30% / 38%

| 变量（暗色） | 上一版 | 现在 |
|---|---|---|
| `--glass-1-top` | `rgb(30 46 92 / 0.66)` | `rgb(26 40 84 / 0.30)` |
| `--glass-1-bot` | `rgb(13 21 44 / 0.58)` | `rgb(10 17 36 / 0.24)` |
| `--glass-2-top` | `rgb(34 52 102 / 0.76)` | `rgb(30 46 96 / 0.38)` |
| `--glass-2-bot` | `rgb(15 24 50 / 0.68)` | `rgb(12 20 42 / 0.30)` |
| `glass-1` blur | 16px | **30px** saturate 1.30 |
| `glass-2` blur | 22px | **38px** saturate 1.34 |

关键点：可读性不靠填充浓度保，靠**模糊**把背后的光斑和图片糊成均匀色，文字对比度依然够（正文 `#e0e0e0` 叠在模糊后的深底上）。

### 2. 首页「实验室」入口移除，换成统计面板

| 格 | 算法 |
